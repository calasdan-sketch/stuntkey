StuntKey / How it works

How it works

The idea is simple. Through the broker, the key does not go where the AI can read it.

The stunt double

In a film, the stunt double does the risky part. StuntKey does the same for your keys. Your AI gets a stand-in and uses that. StuntKey swaps in the real key only at the last moment, outside the AI's sight.

Step by step

  1. You save a key once.

    StuntKey locks it in your computer's keychain: Windows Credential Manager, macOS Keychain, or the Linux keyring.

  2. Your AI asks for a call.

    It says "call this service", or it talks to a local stand-in address. The key is not in its environment.

  3. StuntKey makes the call.

    It adds the real key, sends the request to the right website, and hands back only the answer.

  4. StuntKey keeps watch.

    It blocks the sneaky routes: dumping environment variables, reading your private keys, opening your .env file. With the Claude Code hook, a key that appears in a command's output is hidden before the AI reads it.

You stay in charge

  • Set a daily limit for each key: stuntkey caps show.
  • Stop everything at once: stuntkey stop. Start again with stuntkey resume.
  • See what happened: stuntkey audit.
  • Find keys already lying around: stuntkey scan.

What it does not do

It lowers risk, it does not remove it. It cannot stop an AI misusing a key it is allowed to use, and it does not protect against malware already running as you (anything running as you can read your keychain). Other AI apps (Cursor, Codex, Gemini, Claude Desktop) have no hook for their file tools. It is beta and has not had an independent security review.
